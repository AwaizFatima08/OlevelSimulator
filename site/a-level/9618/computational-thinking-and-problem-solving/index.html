Show answer

Q19Abstract data types · Challenge · Paper 3 style · 7 marks
  1. (a) Describe an algorithm (in steps, not pseudocode) to search a binary search tree for a given value. [4]
  2. (b) The values 10, 20, 30, 40, 50, 60, 70 are inserted in ascending order into an empty binary search tree. State the maximum number of comparisons needed to find a value, and the maximum if the same values had been inserted in the order 40, 20, 60, 10, 30, 50, 70. Explain the difference. [3]
Show answer
  1. (a) Start at the root node. Compare the search value with the value in the current node. If they are equal, the value is found – stop. If the search value is smaller, follow the left pointer; if larger, follow the right pointer. Repeat until the value is found or a null pointer is reached, in which case the value is not in the tree.
    1 mark each for: start at root; compare with current node and stop if equal; go left if smaller, right if larger; repeat until found or null pointer (not found).
  2. (b) Ascending order: 7 comparisons (the tree is a single chain, like a linked list). Second order: 3 comparisons (the tree is balanced, with 3 levels). A balanced tree halves the remaining nodes at each step (O(log n)); an unbalanced tree behaves like a linear search (O(n)).
    1 mark: 7. 1 mark: 3. 1 mark: explanation (balanced vs degenerate tree).

Q60Recursion · Challenge · Paper 3 style · 9 marks

A warehouse robot moves along grid lines, only right or down. Paths(R, C) gives the number of different routes across a rectangle R squares down and C squares across:FUNCTION Paths(R : INTEGER, C : INTEGER) RETURNS INTEGER IF R = 0 OR C = 0 THEN RETURN 1 ELSE RETURN Paths(R - 1, C) + Paths(R, C - 1) ENDIFENDFUNCTION

  1. (a) State the values of Paths(1, 3), Paths(2, 2) and Paths(3, 3). Show your working. [3]
  2. (b) Write an iterative pseudocode function PathsIter(R : INTEGER, C : INTEGER) RETURNS INTEGER that gives the same results for 0 ≤ R ≤ 20 and 0 ≤ C ≤ 20, using a 2D array Table[0:20, 0:20] OF INTEGER. [4]
  3. (c) Give two reasons why the iterative version is better for large R and C. [2]
Show answer
  1. (a) 4, 6 and 20
    M1 Paths(1, C) = C + 1, so Paths(1, 3) = 4 and Paths(1, 2) = Paths(2, 1) = 3. M1 Paths(2, 2) = 3 + 3 = 6; Paths(2, 3) = Paths(3, 2) = 6 + 4 = 10. A1 Paths(3, 3) = 10 + 10 = 20.
  2. (b) FUNCTION PathsIter(R : INTEGER, C : INTEGER) RETURNS INTEGER DECLARE Table : ARRAY[0:20, 0:20] OF INTEGER DECLARE I, J : INTEGER FOR I ← 0 TO R FOR J ← 0 TO C IF I = 0 OR J = 0 THEN Table[I, J] ← 1 ELSE Table[I, J] ← Table[I - 1, J] + Table[I, J - 1] ENDIF NEXT J NEXT I RETURN Table[R, C]ENDFUNCTION
    1 mark each: nested loops over rows 0 to R and columns 0 to C (filled so the cells above and to the left are done first); edge cells (I = 0 or J = 0) set to 1; other cells = Table[I − 1, J] + Table[I, J − 1]; RETURN Table[R, C].

    B1 no repeated calculation / far fewer steps. B1 no call overhead / no stack frames / no stack overflow.
