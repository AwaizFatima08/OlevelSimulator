Q5Abstract data types · Core · Paper 3 style · 5 marks
  1. (a) Give two advantages of implementing a list as a linked list rather than as an ordered array. [2]
  2. (b) Give one disadvantage of a linked list compared with an array. [1]
  3. (c) A linked list implemented in arrays also has a free list. Explain the purpose of the free list. [2]
Show answer
  1. (a) Any two of: items can be inserted or deleted by changing pointers, without moving other items; (with dynamic memory) the list can grow and shrink as needed; insertion/deletion in the middle is quicker for large lists.
    1 mark each.
  2. (b) Items cannot be accessed directly by index – the list must be followed from the start (so binary search cannot be used); extra memory is needed for the pointers.

Q17Abstract data types · Challenge · Paper 3 style · 7 marks
  1. (a) Describe an algorithm (in steps, not pseudocode) to search a binary search tree for a given value. [4]
  2. (b) The values 10, 20, 30, 40, 50, 60, 70 are inserted in ascending order into an empty binary search tree. State the maximum number of comparisons needed to find a value, and the maximum if the same values had been inserted in the order 40, 20, 60, 10, 30, 50, 70. Explain the difference. [3]
Show answer
  1. (a) Start at the root node. Compare the search value with the value in the current node. If they are equal, the value is found – stop. If the search value is smaller, follow the left pointer; if larger, follow the right pointer. Repeat until the value is found or a null pointer is reached, in which case the value is not in the tree.
    1 mark each for: start at root; compare with current node and stop if equal; go left if smaller, right if larger; repeat until found or null pointer (not found).
  2. (b) Ascending order: 7 comparisons (the tree is a single chain, like a linked list). Second order: 3 comparisons (the tree is balanced, with 3 levels). A balanced tree halves the remaining nodes at each step (O(log n)); an unbalanced tree behaves like a linear search (O(n)).
    1 mark: 7. 1 mark: 3. 1 mark: explanation (balanced vs degenerate tree).

Show answer
  1. (a) Start at the first element and compare each element in turn with the search item, until it is found or the end of the array is reached (item not present).

Q20Searching & Big O · Core · Paper 3 style · 5 marks
  1. (a) A bubble sort can be improved by using a Boolean flag. Describe how the flag improves the algorithm. [3]
  2. (b) State the best-case and worst-case time complexity of the improved bubble sort, describing the data that gives each. [2]
Show answer
  1. (a) The flag is set to FALSE at the start of each pass and set to TRUE whenever a swap is made. At the end of a pass, if no swap was made (flag still FALSE), the array is already sorted, so the algorithm stops early instead of doing the remaining passes.
    1 mark each: flag reset each pass; set when a swap happens; algorithm stops when a pass has no swaps.
  2. (b) Best case O(n) – the data is already sorted (one pass, no swaps). Worst case O(n²) – the data is in reverse order.

Q24Searching & Big O · Challenge · Paper 3 style · 8 marks
  1. (a) Write a pseudocode function BinarySearch(SearchItem : STRING) RETURNS INTEGER that searches the global sorted array Names[1:500] and returns the index of SearchItem, or −1 if it is not found. Use an iterative (not recursive) method. [7]
  2. (b) State the maximum number of comparisons with Names[Mid] your function makes for an array of 500 names. [1]
Show answer
  1. (a) FUNCTION BinarySearch(SearchItem : STRING) RETURNS INTEGER DECLARE Low, High, Mid : INTEGER Low ← 1 High ← 500 WHILE Low <= High Mid ← (Low + High) DIV 2 IF Names[Mid] = SearchItem THEN RETURN Mid ELSE IF Names[Mid] < SearchItem THEN Low ← Mid + 1 ELSE High ← Mid - 1 ENDIF ENDIF ENDWHILE RETURN -1ENDFUNCTION
    1 mark each for: Low and High initialised to 1 and 500; loop while Low <= High; Mid calculated with DIV; return Mid when found; Low ← Mid + 1 when Names[Mid] < SearchItem; High ← Mid − 1 otherwise; return −1 after the loop.
  2. (b) 9
    B1 2⁸ = 256 < 500 < 512 = 2⁹, so at most ⌊log₂ 500⌋ + 1 = 9.

  2. (b) The main program sorts the list 8611, 4692, 7027, 3500, 8126, 6050, 5100, 7788 and then searches for 7027 and for 6000. State the sorted list, the number of comparisons returned by InsertionSort, and the two values returned by BinarySearch. [4]

Q30Recursion · Challenge · Paper 4 style · 10 marks
  1. (a) A child can climb a staircase by taking either 1 step or 2 steps at a time. The number of different ways to climb N steps is: Ways(1) = 1, Ways(2) = 2, and Ways(N) = Ways(N − 1) + Ways(N − 2) for N > 2.Write program code for a recursive function Ways(N) and an iterative function WaysIterative(N) that give the same results. (Python shown; Java or VB.NET solutions are equally acceptable.) [6]
  2. (b) State the values returned for N = 5 and N = 10. [2]
  3. (c) The recursive function makes 109 calls in total to calculate Ways(10). Explain why it is very slow for large N and how the iterative version avoids this. [2]
Show answer
  1. (a) def ways(n): if n == 1: return 1 # base case: one step left if n == 2: return 2 # base case: 1+1 or 2 return ways(n - 1) + ways(n - 2) # general casedef ways_iterative(n): if n <= 2: return n a, b = 1, 2 for _ in range(n - 2): a, b = b, a + b return b
    Recursive (3): base case N = 1 returns 1; base case N = 2 returns 2; general case returns Ways(N − 1) + Ways(N − 2). Iterative (3): handles N ≤ 2; keeps the last two values; loop updates them N − 2 times and returns the result.
  2. (b) Ways(5) = 8; Ways(10) = 89
    1 mark each.
  3. (c) Each call makes two further calls, so the same values (e.g. Ways(3)) are recalculated many times and the number of calls grows roughly exponentially; the iterative version calculates each value once (O(n)) by keeping the previous two results.
    1 mark: repeated recalculation / exponential growth. 1 mark: iterative computes each value once / linear time.
