Q1Structure charts & state-transition diagrams · Core · Paper 2 style · 5 marks
  1. (a) State the purpose of a structure chart. [1]
  2. (b) Describe what each of the following shows on a structure chart.(i) An arrow with an empty (hollow) circle at its tail.(ii) An arrow with a filled (solid) circle at its tail.(iii) A small diamond where a module joins the lines to two lower modules.(iv) A curved arrow passing across the lines to some lower modules. [4]
Show answer
  1. (a) To show the modular structure of a program: how the problem is broken down into modules, how modules relate (which module calls which) and what data/parameters pass between them.
    B1 shows decomposition into modules and the relationships/parameters between them.
  2. (b) (i) A data couple – a data item (parameter) passed between modules. (ii) A flag – a Boolean/control value passed between modules. (iii) Selection – only one of the lower modules is called, depending on a condition. (iv) Iteration – the lower modules are called repeatedly.
    1 mark each.

Q11Testing & maintenance · Core · Paper 2 style · 5 marks
  1. (a) Describe the difference between black-box testing and white-box testing. [4]
  2. (b) State one reason why both methods are used. [1]
Show answer
  1. (a) Black-box testing: the tester does not look at the code; test data is chosen from the specification and the actual outputs are compared with the expected outputs. White-box testing: the tester knows the code/structure; test data is chosen to test every path/branch through the code, checking that each path works.
    Black box: 1 mark – code not seen / based on specification; 1 mark – compare expected and actual outputs. White box: 1 mark – code structure is known; 1 mark – tests every path/branch/statement.
  2. (b) Black-box testing checks the program meets the requirements, while white-box testing finds faults in paths that black-box data might never reach.
    B1.

  1. (a) State the five stages of the program development life cycle in order. [2]
  2. (b) Describe what happens in the analysis stage. [2]
  3. (c) Give two items produced in the design stage. [2]
Show answer
  1. (a) Analysis, design, coding, testing, maintenance.
    2 marks for all five in the correct order; 1 mark for all five in the wrong order or four in the correct order.
  2. (b) The problem is investigated and defined: the current system is studied (e.g. interviews, observation, questionnaires) and a requirements specification is produced that states what the new program must do.
    1 mark: investigate/understand the problem. 1 mark: produce requirements specification.
  3. (c) Any two of: structure chart; pseudocode/flowcharts; state-transition diagram; identifier table/data structures; interface (screen) designs; test plan.
    1 mark each.
Q26Development life cycle · Core · Paper 2 style · 5 marks
  1. (a) Describe the waterfall model of program development. [3]
  2. (b) Give one benefit and one drawback of the waterfall model. [2]
Show answer
  1. (a) The stages are carried out one after another in a fixed order; each stage must be completed (and signed off) before the next begins; the output of one stage is the input to the next; there is little or no going back to an earlier stage.
    1 mark each for any three of the points listed.
  2. (b) Benefit: simple to understand and manage, with clear milestones and documentation. Drawback: the client sees a working program only at the end, so changes to requirements are difficult and expensive to make.
    1 mark each.
Q27Development life cycle · Standard · Paper 2 style · 6 marks
  1. (a) Describe the rapid application development (RAD) model. [3]
  2. (b) A start-up in Karachi wants a food-delivery app quickly, but it is not yet sure exactly which features customers want. Explain why RAD is suitable, and give one drawback of using it. [3]
Show answer
  1. (a) Development is done quickly using prototypes; the client gives continual feedback on each prototype, which is improved until it meets their needs; modules may be developed in parallel by small teams, often re-using existing code/tools; little time is spent on detailed planning up front.
    1 mark each for any three of the points listed.
  2. (b) Suitable: prototypes can be shown to the client/customers early and changed as the requirements become clear; a working product is produced quickly. Drawback: needs the client to be available for frequent feedback / less focus on non-functional requirements and documentation / not good for very large projects.
    1 mark each for two reasons linked to the scenario; 1 mark for a drawback.
Q28Development life cycle · Standard · Paper 2 style · 5 marks
  1. (a) Describe the iterative model of program development. [3]
  2. (b) Explain one difference between the iterative model and the waterfall model. [2]
Show answer
  1. (a) A simple version meeting part of the requirements is developed first; the life-cycle stages are then repeated in cycles (iterations), each adding or improving features; each version is tested and reviewed by the client before the next iteration.
    1 mark each for any three of: initial simple version; stages repeated in cycles; features added each time; feedback/review after each iteration; working version available early.
  2. (b) In the iterative model the stages are repeated many times and a working version is available early, whereas in the waterfall model each stage is done once in sequence and the full program is only delivered at the end.
    1 mark for each side of the comparison.
Q29Development life cycle · Challenge · Paper 2 style · 6 marks
  1. (a) Recommend a development model for each project and justify your choice.(i) Software that controls the dosage of an infusion pump in a hospital; the requirements are fixed by safety regulations.(ii) A university in Istanbul wants a student timetable app, and expects students to suggest new features after using early versions.(iii) A small charity in Peshawar needs a donation website within six weeks and the director will meet the developers every week. [6]
Show answer
  1. (a) (i) Waterfall – requirements are clear and fixed; each stage must be completed and fully documented and signed off, which suits safety-critical software. (ii) Iterative – a basic version can be released and improved in repeated cycles using student feedback. (iii) RAD – the deadline is short and the client is available for regular feedback on prototypes.
    For each project: 1 mark for a suitable model, 1 mark for a justification linked to the scenario (accept other models only with a strong scenario-based justification).
Q30Development life cycle · Challenge · Paper 2 style · 6 marks
  1. (a) During the design stage of a library loans system, the team produces an identifier table, a structure chart, pseudocode and a state-transition diagram for the loan status of a book. Explain the purpose of each of these four design outputs. [4]
  2. (b) Explain why time spent on the design stage can reduce the total cost of the project. [2]
Show answer
  1. (a) Identifier table: lists each variable/constant/array with its data type and purpose, so programmers use them consistently. Structure chart: shows the modules, their hierarchy and the parameters passed between them. Pseudocode: describes the algorithm for each module in a language-independent way, ready to be coded. State-transition diagram: shows the states a book can be in (e.g. Available, OnLoan, Reserved, Overdue) and the events that move it between them.
    1 mark for each correct purpose.
  2. (b) Errors and misunderstandings found at design are much cheaper to correct than after coding or release; a clear design also lets several programmers work on separate modules in parallel and makes testing and maintenance easier.
    1 mark each for any two valid points.
