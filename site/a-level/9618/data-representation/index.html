Q1User-defined data types · Core · Paper 3 style · 6 marks
  1. (a) Explain the difference between a non-composite data type and a composite data type. [2]
  2. (b) State whether each user-defined type is composite or non-composite.(i) enumerated(ii) record(iii) pointer(iv) set(v) class [3]
  3. (c) Explain why programming languages allow programmers to define their own data types. [1]
Show answer
  1. (a) A non-composite data type is defined without reference to any other data type (it holds a single value, e.g. an enumerated or pointer type). A composite data type is made up of / refers to one or more other data types (e.g. a record, set, array or class).
    B1 non-composite – not defined in terms of other types / single value. B1 composite – built from other data types.
  2. (b) (i) non-composite (ii) composite (iii) non-composite (iv) composite (v) composite
    3 marks all five correct; 2 marks four correct; 1 mark three correct.
  3. (c) The built-in types may not match the data in the problem; user-defined types make the program easier to read and maintain and let the translator check that only suitable values are used.
    B1 any one valid reason.

Q9User-defined data types · Standard · Paper 3 style · 6 marks

TYPE TSeason = (Spring, Summer, Autumn, Winter)A farmer in Punjab uses a program that plans crops by season.

  1. (a) Write pseudocode for a function NextSeason(S : TSeason) RETURNS TSeason that returns the season after S. The season after Winter is Spring. [4]
  2. (b) Explain why using TSeason is better than storing the season as an integer 1 to 4. [2]
Show answer
  1. (a) FUNCTION NextSeason(S : TSeason) RETURNS TSeason DECLARE Result : TSeason CASE OF S Spring : Result ← Summer Summer : Result ← Autumn Autumn : Result ← Winter Winter : Result ← Spring ENDCASE RETURN ResultENDFUNCTION
    B1 function header and ENDFUNCTION. B1 CASE (or IF) structure on S. B1 Spring→Summer, Summer→Autumn, Autumn→Winter. B1 Winter→Spring and value returned. Accept IF S = Winter THEN RETURN Spring ELSE RETURN S + 1 if the language allows arithmetic on ordinal values.
  2. (b) The code is easier to read and understand (Summer rather than 2), and the variable can only take one of the four valid values, so invalid values such as 7 are rejected.
    B1 readability / self-documenting. B1 restricts to valid values / fewer errors.
