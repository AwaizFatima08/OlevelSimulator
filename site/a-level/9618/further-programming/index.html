Q1Object-oriented programming · Core · Paper 3 style · 6 marks
  1. (a) Define each of these object-oriented terms.(i) class (ii) object (iii) attribute (iv) method [4]
  2. (b) Explain what is meant by encapsulation. [2]
Show answer
  1. (a) (i) A template/blueprint that defines the attributes and methods shared by objects of one type. (ii) An instance of a class, with its own values for the attributes. (iii) A data item (property) belonging to a class/object. (iv) A procedure or function defined in a class that acts on an object's data.
    1 mark each.
  2. (b) Combining the data (attributes) and the methods that act on it in one class, and hiding the data (PRIVATE) so it can only be accessed or changed through the class's own public methods.
    1 mark: data and methods bundled together in a class/object. 1 mark: attributes hidden – accessed only via methods (getters/setters).
Q2Object-oriented programming · Core · Paper 3 style · 4 marks
  1. (a) A transport app has a class Vehicle with attributes RegNumber and MaxPassengers and a method Describe(). The classes Rickshaw and Bus are derived from Vehicle. Explain what is meant by inheritance, using these classes. [2]
  2. (b) Explain what is meant by polymorphism, using the method Describe(). [2]
Show answer
  1. (a) Inheritance means a subclass (derived class) automatically gets the attributes and methods of its parent (base) class. Rickshaw and Bus inherit RegNumber, MaxPassengers and Describe() from Vehicle and can add their own, e.g. Bus could add RouteNumber.
    1 mark: subclass receives attributes and methods of the superclass. 1 mark: applied to Vehicle/Rickshaw/Bus.
  2. (b) Polymorphism allows a method inherited from the base class to be redefined (overridden) in a subclass so that it behaves differently: calling Describe() on a Rickshaw object gives a different output from calling it on a Bus object, even though both use the same method name.
    1 mark: same method name, different behaviour in different classes (overriding). 1 mark: example with Describe() for Rickshaw/Bus.

Q5Object-oriented programming · Standard · Paper 3 style · 6 marks
  1. (a) Explain the difference between inheritance and containment (aggregation) in object-oriented programming. Give an example of each from a school system with classes Person, Teacher and Department. [4]
  2. (b) Explain what is meant by method overriding. [2]
Show answer
  1. (a) Inheritance is an 'is a' relationship: a subclass gets the attributes and methods of a superclass – e.g. Teacher inherits from Person (a teacher is a person). Containment/aggregation is a 'has a' relationship: one class contains objects of another class as attributes – e.g. a Department has (contains) several Teacher objects.
    1 mark: inheritance = 'is a'/subclass gets parent's members. 1 mark: suitable inheritance example. 1 mark: aggregation = 'has a'/object contains other objects. 1 mark: suitable aggregation example.
  2. (b) A subclass defines its own version of a method that it has inherited, with the same name/identifier (and parameters); when the method is called on a subclass object, the subclass's version is used instead of the parent's.
    1 mark: subclass redefines an inherited method with the same name. 1 mark: subclass version runs for subclass objects.

Q7Object-oriented programming · Standard · Paper 3 style · 5 marks
  1. (a) Explain the difference between method overloading and method overriding. [2]
  2. (b) A class Shape has a method Area(). Classes Circle and Rectangle inherit from Shape. A program stores a mixture of Circle and Rectangle objects in one array of type Shape and calls Area() on each element in a loop. Explain how polymorphism makes this possible, and why it is useful. [3]
Show answer
  1. (a) Overloading: several methods in the same class have the same name but different parameter lists (number or types), and the one called depends on the arguments given. Overriding: a subclass redefines a method inherited from its superclass with the same name and parameters.
    1 mark for each correct description.
  2. (b) Each subclass overrides Area() with its own formula. At run time, the version of Area() that runs depends on the actual class of each object, so the same call Area() gives the correct result for every shape. This means the loop does not need IF statements to test the type, and new shapes (e.g. Triangle) can be added without changing the loop.
    1 mark: Area() overridden in each subclass. 1 mark: correct version chosen at run time according to object type. 1 mark: benefit – simpler code / no type checks / easily extended.

Q11File processing & exception handling · Core · Paper 3 style · 5 marks
  1. (a) Describe each of these methods of file organisation.(i) serial (ii) sequential (iii) random [3]
  2. (b) Explain the difference between sequential access and direct access. [2]
Show answer
  1. (a) (i) Records are stored one after another in the order in which they were added (chronological), not sorted. (ii) Records are stored one after another in order of a key field. (iii) Records are stored at an address calculated from the key field by a hashing algorithm, so they can be accessed directly.
    1 mark each.
  2. (b) Sequential access reads records one after another from the start of the file until the required record is reached; direct access goes straight to the required record (using its address/index/hash) without reading the earlier records.
    1 mark for each.

    1 mark each for any three.

  1. (a) State the results of the goal cannot_eat(sara, D). [2]
  2. (b) Explain, using this goal, what is meant by instantiation and backtracking. [4]
  3. (c) Write a goal to find all the dishes that Usman cannot eat, and state its result. [1]
Show answer
  1. (a) D = halwa; D = kheer
    1 mark each.
  2. (b) Instantiation: a variable is given (bound to) a value when a match is found – e.g. I is instantiated to nuts from allergic(sara, nuts), then D to halwa. Backtracking: after a solution is found (or a sub-goal fails), Prolog goes back to the most recent choice point and tries the next possible match – e.g. it returns to contains(D, nuts) and finds contains(kheer, nuts), giving D = kheer.
    1 mark: instantiation definition. 1 mark: instantiation example from the goal. 1 mark: backtracking definition. 1 mark: backtracking example.
  3. (c) cannot_eat(usman, D). Result: D = kheer
    B1 goal and result.
Q25Declarative programming (Prolog) · Standard · Paper 3 style · 5 marks
  1. (a) Describe two features of declarative programming that make it different from imperative programming. [4]
  2. (b) Suggest one type of application for which declarative programming is well suited. [1]
Show answer
  1. (a) In declarative programming the programmer states facts and rules describing the problem (what is true), not the step-by-step method; the language's inference engine searches the knowledge base (with backtracking) to find solutions to goals.     For each of two features: 1 mark for the feature, 1 mark for the contrast with imperative programming (e.g. facts/rules vs sequence of commands; goal-directed search/backtracking vs explicit control flow; no assignment/state change vs variables updated).

    B1.

  1. (a) State all the results of the goal ancestor(rashid, Y), in the order Prolog finds them. [3]
  2. (b) Identify the base case and the general (recursive) case in the definition of ancestor, and explain why the base case is needed. [3]
  3. (c) Write a rule cousin(X, Y) that is true if X and Y are different people whose parents are siblings (two different children of the same parent). [2]
Show answer
  1. (a) Y = sana; Y = imran; Y = ali; Y = zoya; Y = hira
    1 mark: sana, imran first (from the first clause). 1 mark: ali, zoya, hira all present. 1 mark: correct order. (Second clause: Z = sana gives ali then, recursively, zoya; Z = imran gives hira.)
