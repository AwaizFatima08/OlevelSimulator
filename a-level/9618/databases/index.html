Q1SQL queries (DML) · Core · Paper 1 style · 7 marks

A clinic in Faisalabad stores patient data in the table PATIENT. Some of the data is shown.PATIENTPatientID | FirstName | LastName | City | BloodGroup | AgeP101 | Ayesha | Khan | Lahore | O+ | 34P102 | Bilal | Ahmed | Faisalabad | A+ | 51P103 | Sana | Raza | Lahore | B+ | 27P104 | Hamza | Qureshi | Faisalabad | O+ | 45P105 | Mehwish | Iqbal | Multan | O+ | 62P106 | Usman | Tariq | Lahore | O+ | 19P107 | Zara | Malik | Faisalabad | AB- | 38

  1. (a) Write an SQL query to return the first name and last name of every patient with blood group O+ who is older than 30. List the patients with the oldest first. [4]
  2. (b) Write down the output of the query from part (a) when it is run on the data shown. [2]
  3. (c) State the output of this query:SELECT COUNT(PatientID) FROM PATIENT WHERE City = 'Lahore'; [1]
Show answer
  1. (a) SELECT FirstName, LastNameFROM PATIENTWHERE BloodGroup = 'O+' AND Age > 30ORDER BY Age DESC;

  2. (b) Mehwish Iqbal; Hamza Qureshi; Ayesha Khan (in this order).
    1 mark for the correct three patients only, 1 mark for the correct order.

Q3SQL queries (DML) · Standard · Paper 1 style · 6 marks

A school in Quetta has these two tables:STUDENT(StudentID, StudentName, ClassID)CLASS(ClassID, TeacherName, Room)

  1. (a) Write an SQL query to output the name of each student together with the room of that student's class, for all students in classes taught by 'Mr Siddiqui'. [4]
  2. (b) Explain why the attribute ClassID is needed in both tables. [2]
Show answer
  1. (a) SELECT STUDENT.StudentName, CLASS.RoomFROM STUDENTINNER JOIN CLASS ON STUDENT.ClassID = CLASS.ClassIDWHERE CLASS.TeacherName = 'Mr Siddiqui';
    1 mark SELECT StudentName, Room; 1 mark FROM STUDENT INNER JOIN CLASS; 1 mark ON STUDENT.ClassID = CLASS.ClassID; 1 mark WHERE TeacherName = 'Mr Siddiqui'. Accept FROM STUDENT, CLASS WHERE STUDENT.ClassID = CLASS.ClassID AND …
  2. (b) ClassID is the primary key of CLASS and a foreign key in STUDENT; it links each student to one class so the tables can be joined.
    1 mark: primary key in CLASS / foreign key in STUDENT; 1 mark: creates the relationship/link so data from both tables can be combined (joined) without storing teacher and room for every student.

Q5SQL queries (DML) · Standard · Paper 1 style · 8 marks

A weather service stores monthly rainfall readings for one month each year.READINGReadingID | Station | YearTaken | RainfallMMM1 | Lahore | 2023 | 18.4M2 | Murree | 2023 | 41.2M3 | Lahore | 2024 | 22.6M4 | Karachi | 2024 | 5.8M5 | Murree | 2024 | 36.0M6 | Karachi | 2023 | 7.4

Q6SQL queries (DML) · Challenge · Paper 1 style · 8 marks

A sports club in Singapore uses three tables:MEMBER(MemberID, MemberName, JoinDate)COURT(CourtID, Surface, Indoor)BOOKING(BookingID, MemberID, CourtID, BookingDate, StartTime)Indoor is a Boolean field.

  1. (a) Write an SQL query to output the name of each member and the number of bookings that member has made, for bookings of courts that are indoor. Output the members with the most bookings first. [6]
  2. (b) Explain why GROUP BY is needed in your query. [2]
Show answer
  1. (a) SELECT MEMBER.MemberName, COUNT(BOOKING.BookingID)FROM MEMBERINNER JOIN BOOKING ON MEMBER.MemberID = BOOKING.MemberIDINNER JOIN COURT ON BOOKING.CourtID = COURT.CourtIDWHERE COURT.Indoor = TRUEGROUP BY MEMBER.MemberNameORDER BY COUNT(BOOKING.BookingID) DESC;
    1 mark each: SELECT MemberName, COUNT(BookingID); join MEMBER to BOOKING on MemberID; join BOOKING to COURT on CourtID; WHERE Indoor = TRUE; GROUP BY MemberName (or MemberID); ORDER BY COUNT(…) DESC. Accept joins written as conditions in WHERE.
  2. (b) Without GROUP BY, COUNT would give one total for all rows; GROUP BY makes a separate count for each member.
    1 mark: aggregate function COUNT combines rows; 1 mark: GROUP BY makes one result row (count) per member instead of a single overall count.
Q7SQL queries (DML) · Challenge · Paper 1 style · 6 marks

An airline at Islamabad airport wants a list of flight numbers, destinations and departure times for flights to Dubai that still have seats, earliest first. A trainee wrote:SELECT FlightNo Destination, DepartTimeFROM FLIGHTORDER BY DepartTime ASCENDINGWHERE Destination = Dubai AND Seats > 0;The table is FLIGHT(FlightNo, Destination, DepartTime, Seats).

  1. (a) The script contains four errors. Identify three of the errors and write the fully corrected script. [6]
Show answer
  1. (a) Any three of the four errors: (1) SELECT list items must be separated by commas (FlightNo, Destination); (2) the condition is written 'Destination = Dubai' without quotes – a string must be in quotes 'Dubai'; (3) ORDER BY is written before WHERE – WHERE must come before ORDER BY. (4) ASCENDING is not valid – use ASC or omit it.Corrected:SELECT FlightNo, Destination, DepartTimeFROM FLIGHTWHERE Destination = 'Dubai' AND Seats > 0ORDER BY DepartTime;
    1 mark for each error identified (max 3): comma missing between FlightNo and Destination; 'Dubai' not in quotes; clause order (WHERE must come before ORDER BY); 'ASCENDING' should be ASC or omitted. 3 marks for the corrected script: 1 mark SELECT list with commas; 1 mark WHERE Destination = 'Dubai' AND Seats > 0 placed before ORDER BY; 1 mark ORDER BY DepartTime (or DepartTime ASC).

Q9DBMS features · Core · Paper 1 style · 5 marks

A secondary school in Hyderabad stores its data in separate files.

  1. (a) The school's fee office and exam office each keep their own file containing students' names and addresses. Describe two problems this file-based approach can cause. [4]
  2. (b) State how a relational database would reduce one of these problems. [1]
Show answer
  1. (a) Data redundancy: the same student data is stored twice, wasting storage. Data inconsistency: if a family moves and only one office updates the address, the two files disagree.
    Max 2 problems, 2 marks each (identify + describe in context): data redundancy – same data stored in several files; data inconsistency – copies updated in one file but not another; data dependence – programs tied to file structure so changing a file means rewriting programs; difficult to share / search across files.
  2. (b) Student details are stored once in one table and linked to other tables using keys, so there is only one copy to update.
    B1: data stored once / in one table, linked by primary–foreign keys.

Q11DBMS features · Standard · Paper 1 style · 8 marks

A private medical centre in Islamabad stores patient records, appointments and diagnoses in a database.

  1. (a) Describe three ways the DBMS can be used to keep the patient data secure. [6]
  2. (b) Explain why receptionists should be given different access rights from doctors. [2]

Q13DBMS features · Standard · Paper 1 style · 6 marks

A car-rental firm in Lahore has the tables CUSTOMER(CustomerID, Name, Phone) and RENTAL(RentalID, CustomerID, CarReg, StartDate).

  1. (a) Explain what is meant by referential integrity. [2]
  2. (b) The DBMS enforces referential integrity. Describe two actions that would be refused. [4]
Show answer
  1. (a) Every foreign key value must match an existing primary key value in the linked table (or be null), so no record refers to a record that does not exist.
    1 mark: foreign key value must exist as a primary key in the related table; 1 mark: prevents records referring to non-existent records / orphan records.
  2. (b) Adding a RENTAL record with a CustomerID that is not in CUSTOMER would be refused. Deleting a CUSTOMER record while RENTAL records still contain that CustomerID would be refused.
    2 marks each: inserting a child (RENTAL) record whose foreign key does not exist in the parent table; deleting/changing a parent (CUSTOMER) primary key that is still used by child records.
Q14DBMS features · Challenge · Paper 1 style · 6 marks

A regional cricket league in Sialkot keeps player details, team lists, match scores and player medical notes in several spreadsheets, one per team. Many players appear in more than one spreadsheet. Results are also shown on a public website.

  1. (a) Explain how using a relational database managed by a DBMS will improve data integrity, data privacy and data independence for the league, compared with the spreadsheets. Refer to the scenario. [6]
Show answer
  1. (a) Integrity: each player is stored once in a PLAYER table and linked by PlayerID, so there are no conflicting copies; validation rules and referential integrity stop scores being recorded for non-existent players. Privacy: access rights mean coaches can view only their own team's medical data, and the public website account can only read results. Independence: the data dictionary/schema separates the data from the programs, so a new field (e.g. strike rate) can be added without rewriting the scoring and website programs.
    Up to 2 marks for each of the three areas (1 for the DBMS feature, 1 for linking it to the cricket scenario): integrity – single copy, validation, referential integrity; privacy – access rights, passwords, views, encryption; independence – structure held separately in schema/data dictionary so applications unaffected by changes.

Q22E-R diagrams · Standard · Paper 1 style · 6 marks

An online learning platform used across South Asia has STUDENT(StudentID, Name, Country) and COURSE(CourseCode, Title, Hours). A student enrols on many courses and a course has many students.

  1. (a) Explain why the many-to-many relationship between STUDENT and COURSE cannot be implemented directly in a relational database. [2]

    1 mark new link table; 1 mark contains StudentID and CourseCode as foreign keys; 1 mark composite primary key (StudentID, CourseCode); 1 mark two one-to-many relationships replace the many-to-many.

  1. (a) Describe the relationships that should appear in the E-R diagram for DRIVER, CAR, RIDE and PASSENGER, stating the degree of each. [4]
  2. (b) Identify the foreign keys that the RIDE table must contain. [2]
Show answer
  1. (a) DRIVER–CAR: one-to-one (each driver registers one car, each car has one driver). DRIVER–RIDE: one-to-many. PASSENGER–RIDE: one-to-many. CAR–RIDE: one-to-many (optional; implied through driver).
    1 mark each for DRIVER–CAR 1:1, DRIVER–RIDE 1:M, PASSENGER–RIDE 1:M; 1 mark for showing RIDE as the 'many' side holding the foreign keys DriverID and PassengerID.
  2. (b) DriverID and PassengerID.
    1 mark each.

Q25Normalisation · Core · Paper 1 style · 5 marks
  1. (a) State the condition for a table to be in first normal form (1NF). [1]
  2. (b) State the extra condition for a table in 1NF to be in second normal form (2NF). [2]
  3. (c) State the extra condition for a table in 2NF to be in third normal form (3NF). [2]
Show answer
  1. (a) It has no repeating groups of attributes (each field holds a single atomic value).
    B1.
  2. (b) It has no partial dependencies: every non-key attribute depends on the whole of the primary key, not on just part of a composite key.
    1 mark depends on the whole key; 1 mark no partial key dependency (relevant to composite keys).
  3. (c) It has no non-key (transitive) dependencies: no non-key attribute depends on another non-key attribute.
    1 mark no non-key dependencies; 1 mark every non-key attribute depends only on the key.

Q27Normalisation · Challenge · Paper 1 style · 8 marks

A spare-parts dealer in Gujranwala stores invoices as:SALES(InvoiceNo, InvoiceDate, CustomerID, CustomerName, CustomerCity, PartNo, PartName, UnitPrice, Quantity)One invoice can contain many parts; the quantity is for that part on that invoice.

  1. (a) The table is in 1NF with primary key (InvoiceNo, PartNo). Identify the partial dependencies and the transitive (non-key) dependency. [3]
  2. (b) Normalise the data to 3NF. Write each table in the form TABLE(Attribute1, …), with the primary key in capitals, and identify the foreign keys. [5]
Show answer
  1. (a) Partial: InvoiceDate, CustomerID, CustomerName and CustomerCity depend on InvoiceNo only; PartName and UnitPrice depend on PartNo only. Transitive: CustomerName and CustomerCity depend on CustomerID (a non-key attribute).
    1 mark invoice attributes depend on InvoiceNo only; 1 mark part attributes depend on PartNo only; 1 mark CustomerName/CustomerCity depend on CustomerID.
  2. (b) INVOICE(INVOICENO, InvoiceDate, CustomerID) – CustomerID foreign keyCUSTOMER(CUSTOMERID, CustomerName, CustomerCity)PART(PARTNO, PartName, UnitPrice)INVOICELINE(INVOICENO, PARTNO, Quantity) – both parts are foreign keys
    1 mark each table with correct key (4); 1 mark foreign keys correctly identified. Quantity must stay with the composite key.

Q30SQL definition (DDL) · Challenge · Paper 1 style · 10 marks

A city air-quality project in Lahore records PM2.5 readings. Each sensor has a 4-character ID, a location (up to 30 characters) and the date it was installed. Each reading records the sensor ID, the date, the time, the PM2.5 value (decimal) and whether an alert was sent. A sensor takes at most one reading at any date and time.

  1. (a) Write the SQL DDL to create both tables, including all primary and foreign keys and suitable data types. [6]
  2. (b) Write an SQL query to output the location and PM2.5 value of every reading on 14/11/2026 where an alert was sent, highest PM2.5 first. [4]
Show answer
  1. (a) CREATE TABLE SENSOR( SensorID CHARACTER(4), Location VARCHAR(30), Installed DATE, PRIMARY KEY (SensorID));CREATE TABLE AIRREADING( SensorID CHARACTER(4), ReadDate DATE, ReadTime TIME, PM25 REAL, AlertSent BOOLEAN, PRIMARY KEY (SensorID, ReadDate, ReadTime), FOREIGN KEY (SensorID) REFERENCES SENSOR(SensorID));
    1 mark SENSOR table structure; 1 mark SENSOR primary key; 1 mark AIRREADING fields with DATE/TIME/REAL/BOOLEAN; 1 mark composite primary key (SensorID, ReadDate, ReadTime); 1 mark FOREIGN KEY (SensorID); 1 mark REFERENCES SENSOR(SensorID). SENSOR must be created first.
  2. (b) SELECT SENSOR.Location, AIRREADING.PM25FROM SENSORINNER JOIN AIRREADING ON SENSOR.SensorID = AIRREADING.SensorIDWHERE AIRREADING.ReadDate = '14/11/2026' AND AIRREADING.AlertSent = TRUEORDER BY AIRREADING.PM25 DESC;
    1 mark SELECT Location, PM25; 1 mark join on SensorID; 1 mark both WHERE conditions; 1 mark ORDER BY PM25 DESC. Accept any sensible date format, e.g. #14/11/2026#.
